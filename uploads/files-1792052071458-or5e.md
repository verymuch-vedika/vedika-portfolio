# Agent instructions

You are working on **Vedika’s portfolio**, a static site built with Vite and vanilla HTML/CSS/JS.
Read **`DESIGN.md`** before touching any UI. It is the design system and wins over your defaults.

## Hard rules

1. **Use tokens and existing components.** No new colours, fonts, radii or shadows outside the
   scales in `DESIGN.md`. Reuse `.eyebrow`, `.link-arrow`, `.circle-btn`, `.tag`, `.facts`, etc.
2. **No frameworks or new dependencies** unless the user asks. No CSS frameworks, no animation libs.
3. **No em dashes (—) in any visible copy**, titles or alt text.
4. **Respect confidentiality:** case studies use disguised client names.
5. **Portraits are silvertone, covers are `.soft`.** Never add a colour portrait.
6. **Motion:** animate only `transform`/`opacity`; no scroll-driven scaling; respect
   `prefers-reduced-motion`.
7. **Sticky stack invariants** (`.stack-card`): equal heights via `--card-h`, margins that net to
   `--gap`, `--peek: 18px`. If you change card content/size, re-verify the deck releases together.
8. **Timeline invariants:** one stop per year; every card must land exactly on the content line
   (desktop and mobile stepper).
9. **Keep it accessible:** semantic elements, `aria-label` on icon buttons, visible focus.
10. **Don’t delete user content or images** without asking. Placeholders are marked `.cs-fill` / `.cs-ph`.

## Definition of done

- `npm run build` passes, with no console errors.
- Visually verified in a browser at **1440 and 390** (plus any width the change targets), scrolling
  down **and** up through anything sticky or scroll-linked.
- No horizontal overflow; no clipped shadows/text.
- `DESIGN.md` updated if you introduced or changed a pattern.
- Commit with a clear message.
